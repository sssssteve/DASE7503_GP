# 树莓派比赛入口（ROS 2 Jazzy）

## 空车导航与识别

在 Pi 的 SSH 终端运行 `bash ~/DASE7503_GP/code/pi_match/start_match.sh --nav-test`。发车前确认托板已在低位、架下净高足够，把车放在蓝区并对准 START 码。读到 START 后沿中轴依次前往 P1–P4。每架均用雷达定位四腿、停车核码、对准开口，再按实测距离低速钻入。架下停稳并确认托板对中后，原朝向倒退相同距离，再空车经过预设卸货位。四架保留在原位作为障碍；最后停车扫一次 END。测试模式不发送舵机指令。进退通道有障碍或后方雷达覆盖不足时停车。Ctrl+C 中止；正式搬运使用无参数入口。

需要同时监控时，在 Pi 上运行 `bash ~/DASE7503_GP/code/pi_match/start_match.sh --nav-test --monitor`。每 3 秒输出原始和过滤扫描、底盘、里程计、相机信息的接收状态，内核欠压及 USB 事件随到随显示。扫码和钻架进度在同一终端。本轮目录打印在开头，位于 `~/dase7503_logs/`，其中 `run.log` 为终端记录，`nav2.log` 为导航节点日志。Ctrl+C 停止本轮测试及其监控。Mac 单图监看使用 `python3 ~/DASE7503_GP/code/pi_match/mapping_view/local_gui.py --radar`。

空车测试的普通导航在车体系 x 正向和 y 两向限速 0.25 m/s，x 反向限速 0.22 m/s，平移加速和减速上限分别为每轴 0.60、0.75 m/s²。Nav2 按当前路径和障碍决定实际速度。进退架仍限速 0.06 m/s。空车测试把货架和码柱轮廓向外预留 2 cm，再计栅格半对角线；激光预测碰撞减速的前视时间为 0.9 秒。正式搬运使用 4 cm 和 1.2 秒。

终端起步时先静止定位。墙面匹配有多解时，空车低速原地转一圈，每 45° 停车采样，回到原扫码朝向后再次匹配。证据仍不足时停车继续采样。初始位姿采用对应激光扫描的时间戳；提交后直接等待导航节点及坐标变换可用。读到 START 后才出发。

雷达或 ESP32 掉线时，当前终端保留任务，停车等新扫描和底盘反馈。恢复后继续同一目标，进退架按恢复后的地图位姿计算剩余距离。若 ESP32 需要 EN/RESET，保持车静止后按板上按钮即可，原终端保持打开。真实急停、故障或净空不足时不会驱动车辆。正式比赛的 180 秒继续计时；载货或升降时若失去底盘反馈，因无承载传感器，设备恢复后保持停车，等待现场确认承载状态；空车测试无需这项确认。

比赛定位和避障使用 `/scan_body_filtered`。按雷达安装位置把回波换算到车体坐标，过滤范围包括车身轮廓外扩 1 cm（含边界，角部按圆弧）、固定近回波窗口和右缘小框（`scan_mask_box_m`）。框内的真实障碍回波也会被遮蔽；其余有效点按相邻激光束去孤点：前后各两束内至少有一个邻点才保留。允许距离取 `scan_neighbor_gap_m`（当前 3 cm）加两倍束间弦长，上限 10 cm。删掉该配置项可复用原固定 10 cm 容差。单束命中的远处架腿也可能消失。原始雷达话题 `/scan` 可用于网页对照。普通导航避障由 Nav2 代价地图、局部控制器和 Collision Monitor 执行。10 cm 近障及车身扫掠检查只用于自主雷达精对准。该参数不改变地图净空、加载货架时的外形或进退架通道检查。

## 正式比赛（SSH 终端）

在 Pi 解压目录运行 `bash start_match.sh --check` 检查实车配置。首次使用先完成 ROS 环境、驱动和 pi_ws 编译；请填完 match.yaml 中的实测项与四架完整码文。

比赛时把车放在蓝区、相机对准 START，执行 `bash start_match.sh`。若使用单独的配置文件，将其路径作为参数。脚本检查配置，复用已有底盘、雷达、相机话题，按需启动驱动，确认三个数据源有消息后启动定位、导航、扫码和比赛总控。一键入口实际收到相机图像首帧后，总控复用这次检查；出发仍须收到本轮 START 码的解码结果。ESP32 Agent 已运行但无反馈时，保持车静止，按板上 EN/RESET。雷达按 USB 身份识别，同一台 MS200p 在 ttyACM0 和 ttyACM1 间换号时会关闭旧驱动并重连。单独监看可运行 `bash ~/DASE7503_GP/code/pi_match/pi_hardware/pi.sh lidar`。ESP32 优先识别唯一 CP2102，其次 ttyUSB0，接线不同可通过 LIDAR_PORT、ESP_PORT 指定。

START 确认后开始计时。当前 timed 配置按舵机命令行程自动等待；如特意选择 operator 才需要现场确认。保持 SSH 窗口打开；中断比赛按 Ctrl+C。P4 卸货退出、空车读到 END 才完成。本入口直接用终端，不依赖网页。


目标设备是 Raspberry Pi 5、Ubuntu 24.04 ARM64。先用车辆现有底盘固件、Agent、真实 MS200p、真实镜头逐项联调。桌面包根目录“先读我”前四步适用。以下按 Bash 编写，各终端使用同一 ROS 域。源码中的实车流程没有模拟到位依赖。

**准备软件。** 在 Pi 上安装 `ros-jazzy-navigation2 ros-jazzy-nav2-bringup ros-jazzy-slam-toolbox ros-jazzy-cv-bridge python3-opencv python3-zxing-cpp python3-yaml python3-numpy`、colcon 和团队 Agent 依赖。按团队说明在 Pi 上构建消息包和 Agent，并在包内 pi_ws 构建雷达和建图包。默认读取 `~/microros_ws/install/setup.bash`；若位置不同，每个终端 export DASE_CHASSIS_SETUP=/实际工作区/install/setup.bash。相机使用团队 camera_ros/libcamera 环境。不要把 x86 wheel 装到 ARM64。

**准备比赛地图。** 赛前使用真实雷达、轮式里程计和实测安装 TF 建图，保存固定结构的 YAML+PGM。尽量在搬动货架之前用空场巡扫固定障碍。先做巡场回环和实际通道检查。可移动货架通过实时雷达进入代价地图。若把架腿永久写入静态地图，举升后当前位置可能仍被规划器认为被障碍物占据。不要为通行而抹掉实际存在的固定障碍。

**实测填写。** 复制 pi_hardware/match.yaml 并填写比赛图、起始区域边界（或实测固定起始位姿）、雷达外参、空车/载货外接半径、四个完整码文、每个预靠点（均为 *map 坐标系* 的 x、y、yaw）、END 预靠点和退出距离。填写实测的升降角度与速度，及每个方向从收到回执到机构稳定所需秒数。每架填写实测 opening_m（架腿内侧净宽）和 max_insert_m（直进距离上限）。相机只负责读取指定二维码。各格地图点应在可通行区域，目标朝向应使期望二维码可见。

**举升策略。** 固件仅提供接受/拒绝和目标 PWM。可选 `lift_policy: operator` 用于有人联调。在匹配请求号、通道、角度的 accepted 回执及指定等待时间后，总控打印一次性确认命令；目视确认离地/落稳后在另一已加载 ROS 的终端执行。超时自动停下。当前比赛模板采用 timed。等待时间留空时按指令行程、速度和固件加速度计算。timed 没有物理到位检测，卡住也可能被当作完成。成绩和验收应明确该限制。两模式都不订阅 /sim/lift_state。

**启动顺序。**

1. 启动 Agent、ESP32、单独雷达驱动（frame_id=laser_frame、scan_topic=/scan）、已标定的相机。停止上一轮 SLAM 与调试里程计、遥控、扫码节点。比赛入口会启动轮式状态适配器、静态雷达 TF、AMCL、地图服务器、Nav2、扫码节点。若已有 URDF 发布同一雷达 TF，统一为一个发布者后再启动。
2. 在包根目录 `bash pi_hardware/pi.sh config /实际路径/match.yaml`。通过后另开终端 `bash pi_hardware/pi.sh nav /实际路径/match.yaml`，保持运行；该进程默认输出零速，且要求总控续期才放行速度。
3. 开另一个终端 `bash pi_hardware/pi.sh check /实际路径/match.yaml`。检查地图目标、节点匹配、底盘故障、传感器新鲜度、相机画面、扫描时刻的 TF、Nav2 生命周期。此命令会注册 ROS 端点以检查匹配关系，但不发送动作。确认 RViz 中实际车身和激光与场地对齐。check 成功不能代替方向、距离、标定和带载测试。
4. 首次先架空验证轮序、正方向、停止、舵机行程；落地低速验一架。现场确认机器人准备好后运行 `bash pi_hardware/pi.sh run /实际路径/match.yaml`。该命令会实际运动。START 确认后开始 180 秒计时；总控按配置顺序接近、核码、雷达对准、按雷达测得的距离进架、举升、放下、退出。四架完成后空车确认一次 END。请求号续接当前 ESP32 状态。异常将锁存底盘急停；检查现场后根据团队固件说明手动恢复。
5. 首次建议有人在物理停止开关旁观察，记录每趟实测位置、时间和离地状态，带载复测。Pi 持续负载、USB 丢包、相机逆光和举升实际行程须在车上验收。

**要保留的运行证据。** 实机 `uname -m` 应为 aarch64；保留 pi_ws 构建日志、config/check 输出，录制 /scan、/odom、/tf、/tf_static、/chassis/status、/lidar/cmd_vel、/servo/command、/servo/status 及最终观察结果。扫码截图默认在 ~/dase7503_game_evidence。请将模拟画面和真机证据分别保存。

全向导航允许向后、横向平移。MPPI 移除偏好车头沿路径行驶的两项评分，并启用 TwirlingCritic 抑制多余自转；保留碰撞检查和目标朝向控制。各架预靠与卸货位的 yaw 应根据相机取货方向实测设置；朝向不同时车辆仍会转动。实车需核对负 linear.x、后方视野与带载制动。

地图上直线优先：match.yaml 的 path_mode 设为 straight 时，Theta* 优先规划任意角直线段，遇到不可用的结果会回退到 NavFn；MPPI 保持倒车、横移和足迹碰撞检查。整体恢复不主动原地旋转。需安装 ros-jazzy-nav2-theta-star-planner（本次使用的 navigation2 安装已包含）。navfn 使用此前的规划方式；未填写 path_mode 的旧自定义配置沿用 navfn。比赛配置按 P1 → P2 → P3 → P4 执行。车上须按实测坐标、二维码身份和通道净空填写。2026-11-18 的不同顺序对照录像仅用于比较路径，按 P1→P2→P3→P4 的早期试验曾记录到 P2 架腿接触。

## 从起始区域自动定位

在预建地图的 `map` 坐标中量出起始区边界，在 `match.yaml` 填 `start_region: [xmin, ymin, xmax, ymax]`，单位为米。这个矩形限制的是车体中心的搜索位置。若起始区在地图上是斜的，可填包住它的最小轴对齐矩形。配置区域后，`initial_pose` 可留空。

把车放在起始区并停稳。启动 `pi.sh nav` 后运行 `pi.sh check`。程序在起始区内按配置的朝向附近比较候选位姿，三圈雷达扫描一致且 AMCL 回报相符才打印定位通过。每次 `pi.sh run` 也会重新定位，然后才等 START。遮挡、多解或车移动时，程序会停在检查阶段。保留固定围墙的地图更适合这一步。START 码仍用于触发出发。

已使用固定初始位姿的旧配置可以继续使用，将 `start_region` 留空即可。首次实车联调时，从起始区内几个不同位置按约定朝向分别运行检查，并在 RViz 核对两面固定墙是否对齐。

## 比赛扫码与避碰

雷达、相机和 ESP32 已在线时，在 Pi 上执行 `bash pi_hardware/pi.sh auto /实际路径/match.yaml`。该入口启动 Nav2 与视觉节点，完成检查后在 START 等扫码。模板已指向老师 PDF 的固定围墙地图。若配置复制到其他目录，请更新其中的相对路径。

每架的 `rack_hint` 填原场固定架中心和朝向，按 P1、P2、P3、P4 排列 `racks`，用现场二维码替换代码占位符。程序先到 `approach` 扫描三圈，从重复回波中拟合四条架腿，再按实测架位修正接近点。遮挡较多时可在 `scan_views` 填最多两个补扫位。`leg_spacing_m` 填架腿中心沿两轴的实测间距。四条腿不齐、拟合有歧义或二维码不符时，比赛暂停并报告原因。

四腿只在取架前确认。确认举升后用实测载架外形规划，并按实时车体位姿与速度检查接下来约 0.6 秒的扫过范围。本架离地后才从原场障碍中移除，其余未取货架保持占位。卸货确认落稳后，将本架的落位登记为障碍。进架和退出只允许穿过目标架的架下空间，继续检查其他货架、立柱和实时雷达通道。

- 在蓝区手动将车头对准 START 码，保持静止完成雷达定位和扫码。总控停车扫到 START 后开始 180 秒计时。每一趟按 `racks` 配置顺序，停车读对该架完整码、完成雷达对准、举升确认离地，再载架到绿色终点区卸货。每次扫码先停稳并等待相机，常规扫码一轮最多约 10 秒，未读到可重试一轮。错码或超时不会触发下一步。
- P4 落稳并倒退退出后，空车回到 END 扫码位。唯一一次 END 确认成功才报告任务完成。网页保留 START 和终点区域。局部和全局代价地图同时读取原始雷达，把底图之外新出现的障碍加入规划。
- 在 `match.yaml` 填两根立柱底座的地图坐标和半径、实测车与货架尺寸、举升后架中心偏移。现场核对空车最终扫码位能看到 END。固定落位按从里到外安排，预计至少留出 4 cm，其中所有架角都要在终点区内。A–D 按现场确认的搬运顺序保留。
- 规划时载架轮廓覆盖车和整架。确认落稳后，记录当时估算的货架位姿，两根立柱和累积落架继续留在代价地图，等待全局代价地图确认后才倒退。退到架外后恢复空车轮廓。全局路径有站桩和已放货架约束，直线进退还检查原始雷达。前后方向有障碍或缺少扫透的通道证据会停车。现有前置雷达若看不到后方，应补齐后向探测，再验证自动倒退。
- 新开一轮比赛前清空终点区并重启比赛节点。场上已有货架时不要重新从 START 开跑。使用 `pi.sh nav` 和 `pi.sh run` 启动比赛流程。

在 `qr_posts` 登记 START、END 柱底的参考中心和底座外接半径。雷达扫到的柱身或底座会按实际回波位置进入代价地图，并用于载架行驶检查。若现场测到柱子可能移动且有遮挡，可在 `qr_post_shift_m` 为两根柱子分别填最大偏移，扩大地图预留范围。此项可省略，默认 0 m。最终 END 停车位还须留出空车外接半径、5 cm 防撞余量和 6 cm 导航到达容差。停稳并通过间距复核后才扫码。没读到码时在原地重试，仍读不到则停止本轮。

## 可选中轴路线

空车对照测试用 `bash ~/DASE7503_GP/code/pi_match/start_match.sh --nav-test --monitor --direct`。读对 START 后仍向终点墙粗调朝向，随后直接导航到各架的观察位，从架下退出后直接去预设卸货位。两种路线共用同一地图、车身轮廓、限速、避障和扫码流程。省略 `--direct` 即使用原中轴方案。

比赛配置省略 `centerline` 时按原路线直达。本版模板已启用中轴路线。在自己的 `match.yaml` 可调整通道的 `y`、起点侧入口的 `entry_x`、终点侧出入口的 `end_x`。官方图的几何中线是 `y: 1.0`，实际选线按载架净空确定。网页会画出这段通道。

扫 START 后以终点区短墙（地图负 x，180°）为目标朝向。偏差在 25° 内直接导航到中轴入口；偏差较大时只尝试一次原地粗调，之后交给 Nav2 继续导航。空车到达各架的中轴分支点后，转向配置的进架方向，离开中轴到架外观察位。到位时相机面向货架中心。架口偏航超过 30° 时，先按车角的旋转范围和 Nav2 代价地图判断能否回正；若旋转空间不足，只有车身在架口外且后退能拉开距离时才尝试直退 8 cm，停稳后再转一次。回正和退距由定位及里程计复核，受阻时停车复查当前货架。若车进入架口前的近距离范围，总控停车并取消该观察位的导航，按该架预靠距离计算直线后退量。车后雷达净空和已登记障碍允许才倒车，退后重新核对位置和朝向，停稳再读该架完整码；货架首扫最多 3 秒，有画面但未读到本架码，优先保持朝向直退 8 cm，由里程计确认后原地复扫（最多 10 秒）。直退受阻或复扫失败时，优先导航到中轴侧、距架更远的观察位再扫。该远点不作钻架入口。后方扫描不完整时结合新鲜的全局代价地图核对车尾扫过的区域，由 Nav2 BackUp 检查局部碰撞并直退。后方有实测障碍、退路未确认或复扫仍失败时换架外观察位。本架读码成功后才识别四腿、驶向雷达修正的预靠点和钻架。日志输出目标角、实测角和偏差。同一观察位连续两次不可达时，停车换用配置中的备用观察位；所有观察位均受阻或四腿证据不足时，保留当前货架并重新观察。四腿扫描更新最终朝向，精对准后才直进架。举升后先回中轴，以终点墙为目标朝向沿轴走向终点侧，再去终点区的卸货位。落架倒退后经终点侧出入口回到中轴，下一个任务从那里开始。搬运顺序、落位及最终 END 扫码沿用同一套比赛流程。中轴点作为导航目标交给 Nav2，规划使用含墙面、扫码柱和货架的代价地图。

雷达精对准使用实时架腿点估计横向和航向误差。三帧连续满足误差、净宽与停稳条件后才直进。底盘回报插入成功后，还要按车体位姿与托板偏移复核举升中心，才向 ESP32 发上升命令。

END 候选停车位按标注图中码面朝右上方估算。空车在柱子右上方停车、朝左下方读码，角度约 −122°，实际可读性须现场确认。

**本版固定卸货。** 比赛模板使用 fixed 模式。四个 slot 和中轴出入口已预填在 match.yaml；缺少落位时启动检查会拒绝运行。旧区域版 ZIP 可继续独立使用。每段导航将 Nav2 规划器返回的有效路径直接交给 FollowPath，总控不再复查整个中轴段或整条路径的净空。搬运中继续用实时雷达检查，出现新障碍时可停车。

**赛前填表。** 先核对 P1–P4 完整码文、扫码面方向、预靠和补扫点，以及最后空车 END 扫码位。测托板相对车体中心偏移、架腿间距、架下净高、腿内净宽、允许插入距离和退出距离。复核激光外参与底座中心、START/END 柱底范围、舵机接线和带载升降等待时间。模板沿用键盘脚本 S1、130°/30°、20°/秒。确认放稳后直接倒退。车高 18 cm 用于现场验净高；平面规划按车与所载货架的水平外形计算。

新车外廓为 28 × 19 × 18 cm。base_link 为四轮中心，车尾在其后 11 cm、车头在其前 17 cm。雷达中心距车尾 24 cm，在轮组中心前 13 cm，横向居中。空车旋转包络半径为 19.5 cm，Nav2 使用前后不对称轮廓；倒车单独检查从实际后沿扫过的区域。登记架体按几何距离预留 4 cm，地图上的同一禁入余量不再重复叠加。

当前模板按托板与车尾齐平、货架居中承载计算，托板中心在轮组中心后 0.5 cm。系统根据固定架位与车体外形生成预靠位和补扫位。多圈四腿回波估计该架腿距，实时通道射线检查两排架腿的开口，精对准丢失时再补扫并重新核码。退出距离从托板偏移、车体半径与货架纵向半尺寸计算。放货位已按新偏移调整。首次升降按最大 180° 指令跨度预留时间，后续按相邻指令的角差计算，无法检测舵机卡住或架子未离地。

当前场地使用现场架位参考。配置里的 P1–P4 行位置按现场观测相对 PDF 上下对调，两排架体在整段通道的内边分别为 y=0.730 m、1.180 m，取共同通道中线 y=0.955 m。每个中轴目标停车后打印对应该点的地图定位误差，进入目标半径 6 cm、朝向偏差 25° 内开始停车；到点刹停后按沿轴与横向各 6 cm 复核。轻微刹停偏差只重新靠近原目标，实际规划或控制失败才进入绕行和脱困。黄框用于搜索，四腿几何与二维码均须实测。车体左前、右后的两个固定窄窗仅剔除匹配角度和距离的回波，窗内真实障碍也会被遮蔽。车身两侧或车尾外 5 cm 内，如果两束回波只互相支持且端点间距不超过 1 cm，两束均从导航扫描中剔除。前方和远处的双束回波沿用原规则。空载或载架去中轴、卸货位或终点时，连续两次无路或跟踪受阻，优先保持车头向左横移，再看右侧；两侧都不通时再尝试短程靠近原目标或转向。固定路线的纯横移使用 Nav2 DWB，仅采样相应方向的车身 y 速度；检查雷达通道和地图扫掠区域，通过后直接提交等距采样的横向直线给侧移控制器，途中继续做轮廓避碰。每次提交横移后，日志记录控制器、平滑后、避碰后、底盘指令和底盘反馈的有符号 vy 峰值（cm/s），并用里程计报告实际位移。未采到样本会单独标出。用过滤扫描核对车角和通道覆盖，用地图和 Nav2 检查中间点；最多绕开 25 cm 再恢复原目标。中轴进出、前往卸货位或 END 时，导航连续两次受阻且可选侧向绕行失败，会核查车后通道并请求 Nav2 沿车身直退 15 cm，载架时按车架组合外形核查。停稳后记录实测位移，重规划原目标。每退一步重新检查和规划，退路被挡则停车重试，保留任务。钻架测试退出和正式卸架退出时，后方扫描覆盖不全会复核新鲜地图；实测障碍或未知退路会暂停定距动作，停稳后只续走剩余距离。退出期间当前货架的四条腿作为地图障碍，退出后恢复整个货架禁入区。人工中止和比赛计时仍然有效。
